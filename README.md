# AgentGuard

A security gateway between AI agents and company tools. Every tool call an agent makes goes through AgentGuard. The gateway allows it, denies it, masks the data, or holds it for a human to approve, and it records every decision in a tamper-evident log.

Core principle: **never trust the model.** Permissions are enforced in code, outside the model, so an agent that has been fooled by a malicious document still cannot do more than its user is allowed to do. Detecting malicious text is an extra layer, not the main defence.

## Architecture

```
 ┌──────────────┐  MCP + user JWT   ┌──────────────────────────────────────┐   MCP    ┌──────────────────┐
 │  Demo agent  │ ────────────────► │           AgentGuard gateway         │ ───────► │  Finance tools  │
 │ (Spring AI)  │ ◄──────────────── │  identity · policy · masking ·       │ ◄─────── │  (MCP server)    │
 └──────────────┘  result/decision  │  approval · audit                    │          └────────┬─────────┘
                                    └───────┬──────────────────┬───────────┘                   │
 ┌──────────────┐  REST + WebSocket         │                  │                               │
 │  Dashboard   │ ◄─────────────────────────┘                  ▼                               ▼
 │ (React)      │                     ┌────────────────────────────────────────────────────────────────┐
 └──────────────┘                     │ Oracle Database Free 23ai: schema AGENTGUARD | schema FINANCE │
                                      └────────────────────────────────────────────────────────────────┘
```

The active policy is [gateway/src/main/resources/policies.yml](gateway/src/main/resources/policies.yml): 14 rules, deny by default.

Design, request flow, policy format and threat model: [docs/DESIGN.md](docs/DESIGN.md). Decisions and their reasons: [docs/DECISIONS.md](docs/DECISIONS.md). Demo script: [docs/DEMO.md](docs/DEMO.md).

## Stack

Java 21, Spring Boot 4.1.2, Spring AI 2.0.2 (MCP over Streamable HTTP), Spring Security, Spring Data JPA, Flyway, Oracle Database Free 23ai, JUnit 5 + Testcontainers, Docker Compose, GitHub Actions. Dashboard: React, Vite, Tailwind.

## Modules

| Module | What it is | Port |
|---|---|---|
| `finance-tools` | Demo upstream: an MCP server with 10 tools over a synthetic finance database (suppliers, employee, invoices, documents). All data is generated by a seed script. | 8081 |
| `gateway` | The product. MCP server towards agents, MCP client towards upstream tools, with the policy engine, masking, approvals and audit log. | 8080 |
| `demo-agent` | A chat agent that uses the tools through the gateway. Model provider chosen by `AI_PROVIDER` (`ollama` or `openai`). | 8082 |
| `dashboard` | Live decisions, approval queue, policy viewer, audit search, metrics. | 5173 |

## Run it

Requirements: Docker, Java 21. Maven is downloaded by `./mvnw`.

```bash
cp .env.example .env          # set the three database passwords
docker compose up -d oracle   # first start takes about a minute
./mvnw -pl finance-tools spring-boot:run
```

In a second terminal, the gateway:

```bash
./mvnw -pl gateway spring-boot:run
```

Get a token for a demo user (`fm.amrani`, `accountant.salma`, `clerk.omar`, `hr.imane`, `admin.youssef`, `admin.nadia`, ...):

```bash
curl -X POST localhost:8080/auth/login -H 'Content-Type: application/json'      -d '{"username":"accountant.salma","password":"<DEMO_USER_PASSWORD>"}'
```

Then point any MCP client at `http://localhost:8080/mcp` with `Authorization: Bearer <token>`.
The finance tools on port 8081 refuse every call that does not come from the gateway.

Everything in containers: `docker compose --profile full up --build`.

Tests (they start a real Oracle with Testcontainers): `./mvnw verify`.

Verify the audit chain from the command line (exit code 0 if intact, 1 if not):

```bash
java -jar gateway/target/gateway-*.jar --verify-audit
```

## Limits

This is a gateway, not a guarantee. It does not protect against a compromised gateway host, a database administrator, or stolen user credentials. The untrusted-content scanner uses simple rules and will miss clever attacks; the design accepts that because the permission checks do not depend on it. See the threat model in `docs/DESIGN.md`.
